# 场景参考：扫描版 PDF → 结构化笔记 → Obsidian 落库

这是触发本 skill 的典型场景（把一批资料全量整理成结构化笔记）。本文件给出可复用的执行顺序与检查要点。

## 执行顺序

1. **锁定全集边界**：读取 PDF 元数据得到准确总页数 N，写入 `universe.total = N`。不要凭目录或猜测。
2. **读懂落库规范**：确认 Obsidian 库路径、笔记目录、命名规则、是否有模板、是否需要 MOC/索引。用户提到"仓颉 Skill"时，先确认它的具体调用方式；若无法确认，向用户索要，不要假装会用。
3. **建立清单**：至少包含下列四组检查项（详见 `acceptance_checklist.template.json`）。
4. **全量 OCR + 结构化**：用脚本遍历全部 N 页，逐页产出带页码标识的文件，如 `output/p001.md` … `output/p0NN.md`；每产出一页就把页码追加到 `qa/processed_pages.txt`。
5. **落库**：按规范写入 Obsidian 对应目录，更新索引。
6. **门禁 → 修复 → 回归**：按 SKILL.md 的 Phase 3/4 跑闭环。
7. **交付自检报告**。

## 四类必备检查项

- **覆盖度**：`coverage` 验证器，`expected = N`，证明 N/N 页都有产出。
- **内容质量**：逐页文件非空、关键字段存在、表格转 Markdown、无 OCR 乱码/水印残留。
- **落库核对**：目标目录笔记数 = N（count 验证器）；MOC/索引含全部入口。
- **缺陷扫描**：自定义脚本扫描全集，查乱码、空白占位、断行、页码丢失。

## 让"全量"由代码保证

优先写一个遍历脚本处理全集，而不是让模型逐页记忆：

```python
# 伪代码：全量遍历是机械的，不会挑页
import os
for i in range(1, total_pages + 1):
    text = ocr(pdf, page=i)
    write(f"output/p{i:03d}.md", format_note(text, page=i))
    with open("qa/processed_pages.txt", "a") as f:
        f.write(f"{i}\n")
```

配套缺陷扫描脚本同样遍历全集，把"一处错误"自动升级为"全类错误"的检查：

```bash
# 查空白占位/乱码标记，命中即非零退出
grep -rnE '\[OCR_FAIL\]|\[乱码\]|^\s*$' output/ && exit 1 || exit 0
```

## 特别注意

- **页码对齐**：笔记必须保留原页码标识，便于用户回查和门禁核对。
- **表格无损**：资料报告常含大量表格，表格数量应与原文一致；数量对不上要作为缺陷项处理。
- **不要假设工具可用**：环境里没有 OCR 工具或"仓颉 Skill"不可调用时，如实报告并请求用户配置，不要用"看起来整理好了"的文本糊弄。
- **索引完整性**：落库后从 Obsidian 索引能跳转到全部 N 篇笔记，是"可用"的一部分，不是可选项。
