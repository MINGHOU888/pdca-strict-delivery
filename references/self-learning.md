# 自学习工程：双环 PDCA 与防衰减

本 skill 是**双环**结构。只跑内环会"每次都重新犯错"，加上外环才能越用越强。

## 两个环

- **内环（单次任务）**：P→D→C→A→交付，保证这一项工作做对、做完、可复核。见 `pdca-loop.md`。
- **外环（跨任务/跨轮次）**：把内环 C 阶段发现的缺陷，提炼成可复用经验存进**经验库（playbook）**；下一项工作的 P 阶段开工前加载经验库，把经验转成**预防性检查项**注入清单。同样的坑第二次就在计划阶段被挡住，而不是等做完再返工。

## 经验库

文件路径约定：项目根 `qa/playbook.json`（用 `scripts/playbook.py init` 创建）。每条经验含：

| 字段 | 含义 |
|------|------|
| `pattern` | 问题模式：什么样的缺陷（"表格转 Markdown 时合并单元格丢内容"） |
| `cause` | 根因：为什么会发生（"按行逐格读取，没处理 rowspan"） |
| `method` | 最优解：可复用的正确做法（"先解析 rowspan/colspan 再输出"） |
| `verify` | 如何变成检查项（"扫产物中合并单元格数量 = 原文"） |
| `when` | 适用场景标签（如 `表格`, `OCR`, `编码`），供 P 阶段按标签筛 |
| `status` | `candidate` / `proven` / `deprecated` |
| `applied` / `effective` | 应用次数 / 确实防住问题的次数 |

## 外环四步

1. **C 阶段提炼**：门禁抓出缺陷、同类全量扫描、根因确认后，若该缺陷具有可复用性（非一次性笔误），立即写入经验库：`playbook.py add ...`，填全 pattern/cause/method/verify/when。
2. **P 阶段注入**：`playbook.py list --when <本任务标签>` 取回适用经验，逐条转成预防性检查项加入 `acceptance.json`（id 用 `EXP-xx` 前缀），在 P2 执行时就按最优解做，从源头避开旧坑。
3. **C 阶段验证**：若某经验确实在本轮挡住了同类问题（或用户确认方法有效），`playbook.py mark --id ... --effective --evidence "门禁实跑输出/用户确认"`——`--evidence` 必填，无证据不计有效、不晋升；仅用过则 `--applied`。
4. **晋升与固化**：带证据的 `effective >= 2` 才晋升 `proven`，证据留存在 `evidence_log`。proven 经验是固化进默认清单模板的候选，让以后所有任务天生带这条防护。

## 防衰减机制（越用越强，不会退化）

光有经验库不够——经验会过时、重复、被证伪，不治理反而越用越乱。三条机制保证不衰减：

1. **重复触发 = 强制升级**：`add` 时用相似度匹配（difflib），发现相同/近同 pattern 已存在，不新增重复条目，而是**升级原条目**（method 换成新解法、version+1、status 打回 `candidate`、统计清零）。含义：同一个坑又踩了，说明上次的方法不够好，必须 sharpen，而不是让经验库堆满近义条目。`playbook.py check` 会揪出"升级过却从未验证有效"的条目，并在超过 20 条时告警归档。
2. **有效性统计 + 状态机**：`candidate → proven → deprecated`。只有被验证有效的经验才晋升并固化；被更好方法替代或失效的标记 `deprecated`，P 阶段不再注入。避免错误经验长期污染计划。
3. **迭代上限触发经验升级**：内环 5 轮仍不过时，不要只如实报告就结束——把"为什么反复修不好"作为最高价值缺陷，深度提炼成一条新经验写入库（或在旧经验上升级），供下个任务使用。失败被转化成知识，因此系统不会在同一类任务上反复卡死。

## 每次交付的经验记录

自检报告增加"本轮经验"一节：注入了哪几条经验、验证结果、新增/升级了哪几条。让经验流动可追溯。

## 给无工具 AI 的降级版

无脚本环境：用文字版——在本子/对话里维护一张"教训清单"（问题→根因→最优解），每次开工先读一遍，发现可复用问题就追加，重复出现就改写原条目。机制相同，只是靠自律而非脚本。见 `assets/自学习全量交付PDCA.md`。
